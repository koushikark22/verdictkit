Decisions:
- DD8-1 Threat_Model rows come from D8.4. Every control has a test id or the row is UNTESTED with a reason (13.1 to 13.3).
- DD8-2 (M-1) The vault key is never an argument of any process. Contract: not in any argv or `/proc/<pid>/cmdline`, not in the environment of any process except the custodian (preferably not there either), not in a descriptor inherited by the examiner, not in a file readable by the examiner's OS user, not in any log. Recommended mechanism: the root entrypoint writes the key with shell builtins to a custodian-owned mode 0400 file on tmpfs, unsets the variable, starts the examiner with the closed list, and the custodian reads the file once (`VK_VAULT_KEY_FILE` names the path), validates owner and mode, and removes it. `VK_VAULT_KEY` in the environment stays supported for non-container runs. Alternatives (inherited pipe) are accepted only if they pass the same tests. Tests KT-1 to KT-8: cmdline polling at 1 ms during 20 starts, environ of every process, `/proc/<pid>/fd` of the examiner, a bounded file-system search as the examiner uid, logs of all processes, the entrypoint under `bash -x` in a test copy, a crash message, raw, base64, hex and URL-encoded forms of a canary key. R-1 stays accepted.
- DD8-3 (M-2) Uploaded replay content never enters the trusted evidence root. Each replay gets a server-generated namespace `^[0-9a-f]{32}$` under a separate replay root, removed in `finally`, with orphans swept at start. Metadata (index, URIs, media types) stays in custodian-private scratch. The examiner reads a replay namespace read-only through a validated namespace key and re-hashes on read. A per-replay byte quota and a total replay quota apply. The carrier of the namespace key is chosen at implementation (OD-D8-2). The trusted root listing and hashes are identical before and after any replay.
- DD8-4 (L-7) Admission before buffering. A process-wide semaphore (`VK_MAX_CONCURRENT_UPLOADS`, default 2) is taken in the middleware before the first body read. No slot gives 429 `RATE_LIMITED` with `Retry-After` after reading headers only. Content-Length precheck stays. The body is accumulated once into a bounded buffer, with no second copy. In-flight bytes are bounded by slots times cap by construction. A total body deadline frees slow slots. The slot is released on disconnect and on error. The same admission serves every upload route. No queue or worker is added.
- DD8-5 (L-6) MCP approved roots. `VK_MCP_BUNDLE_ROOTS` (list of absolute directories) plus the private working directory by default. Resolve each root once at start and pin it. Reject NUL, relative paths, UNC paths, `\\?\` and `\\.\` prefixes, alternate data streams and names that Windows aliases (trailing dot or space). POSIX: open component by component with `O_NOFOLLOW` and `dir_fd`. Windows: open each component without following reparse points and reject any reparse point below the root (symlink, junction, mount point, cloud placeholder), then check the final path of the opened handle is under the root. Verify a regular file and the size cap on the opened handle, not on the path. One error code `PATH_NOT_ALLOWED` with a fixed message that echoes nothing. One shared helper is reused by the scaffold destination and the replay scratch (M-7). This is a behaviour change for clients that pass arbitrary paths. 9.1 is amended and the release notes list it. R-D4-3 is resolved.
- DD8-6 (L-3, OD-D3-4 decided) Windows needs CPython 3.12.4 or later for the private-directory property. `requires-python` is not changed (no lock churn). The BE-1 Windows helper fails with `UNSUPPORTED_PYTHON_PATCH` on 3.12.0 to 3.12.3 and does not skip. `mcp_server._workdir` self-checks the new directory on Windows and refuses to start with `PRIVATE_DIR_UNSAFE` when the check fails (fail closed). The elevation state is recorded (CPython 157876). The image's resolved Python patch version goes into release provenance.
- DD8-7 (L-3) Windows oracle evaluation. O1: exact structural allowlist of the access list (protected, no inherited entry, allow entries only, trustees limited to the owner SID, OWNER RIGHTS, SYSTEM, Builtin Administrators; none for Everyone, Authenticated Users, Builtin Users, Guests). O2: `GetEffectiveRightsFromAclW` (AM-D3-2). O3: `AuthzAccessCheck` with synthetic client contexts. Findings: Microsoft says O2 may be unavailable later, it ignores implicit owner rights, privileges and logon-session groups, and it fails on an inherited deny entry, so a pass of O2 alone would not show that Everyone has no access. O1 is exact for a directory this project creates and needs two `ctypes` calls. O3 is the documented method for effective access, but a synthetic context needs a user SID plus added group SIDs (about ten calls and several structures), and `AuthzInitializeContextFromSid` may query the account object. Decision: O1 is required and sufficient for BE-1 closure. AM-D3-2 is amended: O2 is dropped. O3 is a timeboxed spike (S-AUTHZ) on the Windows host that is adopted only if it agrees with O1 on six constructed access lists, including an Everyone entry and an inherited entry, in at most 120 lines with no new dependency. If it is not adopted the record says NOT_ADOPTED with the reason. Its absence does not block BE-1 closure. BE1-6 negative controls stay.
- DD8-8 BE-2 plan. Instrumentation fields (UTC and monotonic): client send, bridge accept, upstream connect start and end with exception class and errno, response write, client first byte, total. At least 30 trials per host, minimum, median and maximum reported. Hypotheses: H1 a refused loopback connect takes about 2 s on Windows; H2 another process owns port 65534 or filtering software delays the connect; H3 the bridge thread model (`ThreadingHTTPServer`) adds delay; H4 the client socket timeout accumulates connect and read; H5 the delay is test-only. A standalone `connect_ex` probe to a closed loopback port on both hosts discriminates H1. The Linux leg is a full-checkout run (the CI job `security-and-regression` or a bind-mounted checkout in a Linux_Docker_Host), because the image lacks `ui/`. Fix rule: if H1 is confirmed, bound the bridge's upstream connect with a dedicated connect timeout below the client's deadline (default 1.0 s, set by `VK_BRIDGE_CONNECT_TIMEOUT`), keep the 10 s read timeout, leave the test assertion and its 2 s client timeout unchanged, and replace the hard-coded port by a closed port allocated at run time (override `VK_TEST_CLOSED_PORT`, 1.17). If H1 is not confirmed the root cause is recorded and a different fix follows. A longer test timeout alone is never accepted (13.12). Closure needs 30 of 30 passes on both hosts with `-rA` and the direct exit code (13.13). The BE-2 attribution wording stays "observed on Windows" until the Linux run exists.

The method is in `docs/next-phase/EVIDENCE_REDACTION.md` and was applied once, to `records.jsonl`. History already published cannot be rewritten without a force push, which is not permitted, so earlier text stays and is listed as residual.
- DD8-10 (L-1) Isolation semantics. S1 the mode is fixed at start-up and never changes while the process lives. S2 when `VK_EXAMINER_SOCKET` is configured, ENFORCED is required: failure to authenticate the examiner refuses the call or the start, never falls back to in-process examination. S3 only an absent `VK_EXAMINER_SOCKET` in the local profile yields UNENFORCED, and every output labels it. S4 the public profile refuses UNENFORCED at start-up. S5 loss of the examiner after start fails the request closed and does not change the mode. S6 `SocketExaminer` without an expected uid is test-only and is refused in the public profile. S7 a replay never raises the recorded mode of a bundle and reports its own mode separately.
